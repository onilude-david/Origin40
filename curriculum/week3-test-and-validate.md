### Monday Guest Mentor Masterclass — Validation, Traction & Growth Loops

**Duration:** 1-2 hours.
**Ideal mentor:** growth lead, sales operator, UX researcher, product manager, founder, or investor
who understands early traction and customer evidence.

**Class flow:**
1. Why opinions are weak and behavior is strong.
2. How to run user tests without leading the user.
3. Early traction signals: usage, signups, pilots, repeat intent, pre-orders, sales conversations.
4. Live work: each founder writes 3 user tasks and one meaningful traction metric.
5. Growth clinic: choose one channel or audience to test before Friday.

**Build consequence:** every founder leaves Monday with a tester list, a test script, and a real
traction metric that can be measured in the same week.

### Friday Demo Gate — Evidence Beats Claims

Each founder has 5 minutes to show:

1. The v1 product/prototype.
2. What real users did with it.
3. The top friction points.
4. What changed in v2.
5. A traction signal or honest evidence of weak demand.

Mentors score the strength of evidence, quality of iteration, and honesty of learning.

## Module 3.1 — Put It in Front of Real Users

### Lesson 3.1.1 — Design a user test
**Description:** Testing is not "do you like it?" — it's watching real people try to get the job done.
**Learning objectives:** Write a task-based test plan; define what success/failure looks like.
**Assignment:** User Test Plan with 3 tasks and a success metric for each.
**Submission:** Test Plan link + summary.
**Worksheet — User Test Plan:**
| Task | What they must do | Success looks like | What I'll watch for |
|---|---|---|---|
| 1 | | | |
| 2 | | | |
| 3 | | | |
Plus: recruiting plan (where 5 testers come from), and your single key question.
**Reflection:** What result would tell you the product is *not* working? Be willing to see it.
**Mentor rubric (/10):** Task-based, not opinion-based (4) · Clear success criteria (3) · Recruiting realism (3).

### Lesson 3.1.2 — Run 5 user tests
**Description:** Watch 5 people use it. Don't help, don't explain — observe.
**Learning objectives:** Conduct tests; capture friction without rescuing the user.
**Assignment:** Complete **5 user tests**; log results.
**Submission:** Feedback Log link + top 5 friction points.
**Worksheet — Feedback Log:** Tester · Completed task? (Y/N) · Where they got stuck · Best quote ·
Feature requested · Would they use it again? (Y/N/Maybe).
**Reflection:** Where did users struggle that *you* thought was obvious?
**Mentor rubric (/10):** 5 tests done (4) · Observed not led (3) · Honest capture (3).

## Module 3.2 — Learn & Iterate

### Lesson 3.2.1 — Synthesize feedback & decide
**Description:** Turn raw feedback into a ranked, decisive change list. Patterns > one loud voice.
**Learning objectives:** Group feedback into themes; separate must-fix from noise; pick top 3 changes.
**Assignment:** Insight synthesis + your top-3 prioritised changes (with reasons).
**Submission:** Add to report doc.
**Worksheet — Synthesis:** Theme · # of users who hit it · severity (blocks value? Y/N) · decision (fix now / later / ignore).
**Reflection:** Which change is hard to make but clearly right? Commit to it.
**Mentor rubric (/10):** Patterns over anecdotes (4) · Sound prioritisation (3) · Decisiveness (3).

### Lesson 3.2.2 — Ship iteration v2
**Description:** Make the top changes and re-test the riskiest one.
**Learning objectives:** Implement priority fixes; verify the fix actually helped.
**Assignment:** Ship v2 of the core flow with your top fixes.
**Submission:** Updated live link / Loom (≤3 min) showing before→after on the key issue.
**Worksheet — Change log:** What I changed · Why · Did re-test confirm it? (Y/N).
**Reflection:** Did the fix move the metric, or just feel better? Trust the evidence.
**Mentor rubric (/10):** Right fixes shipped (4) · Re-tested (3) · Visible improvement (3).

## Module 3.3 — Show Traction

### Lesson 3.3.1 — Define & capture a traction signal
**Description:** Early traction = any honest evidence people want this: signups, usage, waitlist, pre-orders, repeat use.
**Learning objectives:** Pick one true traction metric; set up the simplest way to measure it.
**Assignment:** Choose your traction metric and start a Traction Tracker.
**Submission:** Traction Tracker link + current number.
**Worksheet — Traction Tracker:** Metric chosen · how measured · baseline · daily count (Mon–Fri) ·
1 "proof" artefact (screenshot of signups/usage/messages).
**Reflection:** Is this metric a *vanity* number or a *value* number? Prefer value (use, retention, pay).
**Mentor rubric (/10):** Metric is meaningful (4) · Real evidence captured (3) · Honesty (3).

### Lesson 3.3.2 — Submit the Validation Report (Week 3 Milestone)
**Description:** Tell the story of what you learned and proved.
**Learning objectives:** Present evidence that the problem is real and the solution helps.
**Assignment — MILESTONE:** Submit the **Validation Report**.
**Submission:** Google Doc + updated product link, via LMS.
**Worksheet — Validation Report (template):**
1. What we tested · 2. With whom (5 testers) · 3. Top 3 insights · 4. What we changed (v2) ·
5. Traction signal + proof · 6. What we now believe · 7. Biggest open risk.
**Reflection:** What's the strongest single piece of evidence you'd put in front of an investor?
**Mentor rubric — Week 3 Milestone (/10):** Real user evidence (3) · Iteration quality (2) ·
Traction signal (3) · Clarity of learning (2).

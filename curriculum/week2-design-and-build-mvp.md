### Monday Guest Mentor Masterclass — MVP Architecture & Rapid Prototyping

**Duration:** 1-2 hours.
**Ideal mentor:** product builder, CTO, senior product designer, no-code expert, or founder who has
shipped early products quickly.

**Class flow:**
1. MVP vs. prototype vs. demo: what must be real this week.
2. The one-user, one-job, one-flow rule.
3. Tooling options: no-code, low-code, code, Figma, manual back office, AI-assisted build.
4. Live teardown: cut each founder's feature list down to the smallest valuable slice.
5. Build clinic: founders choose tools, risks, and fallback plans.

**Build consequence:** every founder leaves Monday with a build path that can realistically produce
a Friday demo.

### Friday Demo Gate — Core Flow Works

Each founder has 4 minutes to show:

1. The target user and one job.
2. The product/prototype opening screen.
3. The single happy-path flow from start to value moment.
4. What is real, what is manual, and what is still broken.
5. The test plan for Week 3.

Mentors score whether the product is small enough, usable enough, and connected to the Week 1
problem evidence.

## Module 2.1 — Scope the Smallest Valuable Product

### Lesson 2.1.1 — Define the core value & cut everything else
**Description:** An MVP is not a small version of everything — it's the *one* thing that delivers value.
**Learning objectives:** Identify the single core action; cut features ruthlessly; define "done for v1".
**Assignment:** Write your MVP scope: 1 core user, 1 core job, 1 core flow.
**Submission:** MVP Scope Sheet link + summary.
**Worksheet — MVP Scope Sheet:**
| Field | Answer |
|---|---|
| The one user | |
| The one job they hire it for | |
| The single happy-path flow (step 1 → done) | |
| In scope for v1 (max 3 things) | |
| Explicitly NOT in v1 | |
| Definition of "v1 done" | |
**Reflection:** What did you cut that hurt to cut? Good — that's focus.
**Mentor rubric (/10):** Tight scope (4) · Clear core value (3) · Realistic for 1 week (3).

### Lesson 2.1.2 — Map the build & choose the lightest tools
**Description:** Pick the fastest path to a usable thing — no-code, low-code, or code. Time > elegance.
**Learning objectives:** Choose a build approach; list the steps; estimate effort honestly.
**Assignment:** Build plan with tools + a day-by-day mini-plan (Tue–Thu).
**Submission:** Build Plan in scope doc.
**Worksheet — Build Plan:** Approach (no-code/low-code/code) · tools · key screens/endpoints ·
day-by-day tasks · biggest technical risk · fallback if blocked.
**Reflection:** Where will you be tempted to over-build? Pre-commit to stopping there.
**Mentor rubric (/10):** Fastest sensible path (4) · Realistic plan (3) · Risk awareness (3).

## Module 2.2 — Design the Experience

### Lesson 2.2.1 — Sketch the happy path
**Description:** Design the single flow before you build it. Paper/Figma sketches save days.
**Learning objectives:** Produce a low-fidelity flow of the core journey; remove dead ends.
**Assignment:** A clickable Figma prototype OR labelled wireframe sketches of the happy path.
**Submission:** Figma/image link + summary.
**Worksheet — Flow checklist:** entry point → core action → value moment → next step. Each screen:
what the user sees, what they do, what happens next.
**Reflection:** Where could a first-time user get confused or stuck? Fix it now, it's cheap.
**Mentor rubric (/10):** Clear happy path (4) · Usability (3) · Matches the scope (3).

### Lesson 2.2.2 — Brand & first impression (lightweight)
**Description:** Just enough polish to be credible — name, one-line value, consistent colours.
**Learning objectives:** Apply a minimal, consistent visual identity; write your value proposition.
**Assignment:** Product name + one-line value prop + a simple style (logo/colour/font).
**Submission:** Add to build doc.
**Worksheet:** "[Product] helps [user] [achieve outcome] without [pain]." + 2 colours + 1 font.
**Reflection:** Would a stranger understand what this is in 5 seconds?
**Mentor rubric (/10):** Clear value prop (4) · Credible look (3) · Consistency (3).

## Module 2.3 — Build It

### Lesson 2.3.1 — Build the core flow
**Description:** Heads-down build of the single happy path. Ugly-but-working beats pretty-but-broken.
**Learning objectives:** Ship a usable end-to-end core flow; keep a build log.
**Assignment:** Working core flow (even if rough) + build log of what works / what's faked.
**Submission:** Live link / Loom walkthrough (max 3 min).
**Worksheet — Build log:** Done · Faked/manual (Wizard-of-Oz is fine) · Broken · Tomorrow.
**Reflection:** What's real vs. smoke-and-mirrors? (Faking back-end work for v1 is allowed.)
**Mentor rubric (/10):** Core flow works (5) · Effort/progress (3) · Honest about gaps (2).

### Lesson 2.3.2 — Submit MVP v1 (Week 2 Milestone)
**Description:** Get your prototype in front of mentors before users see it next week.
**Learning objectives:** Demonstrate the core value in under 3 minutes.
**Assignment — MILESTONE:** Submit **MVP/Prototype v1**.
**Submission:** Live URL or Figma + a ≤3-min Loom demo + the MVP Scope Sheet, via LMS.
**Worksheet — Demo script (30-60-90 sec):** 0:00 problem · 0:30 the one flow · 1:30 value moment ·
2:30 what's next. 
**Reflection:** Does the demo show the value, or just features? Cut anything that isn't the value moment.
**Mentor rubric — Week 2 Milestone (/10):** Works end-to-end (3) · Solves the stated problem (3) ·
Scope discipline (2) · Demo clarity (2).
